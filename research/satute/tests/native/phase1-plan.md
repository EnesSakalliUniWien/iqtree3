# SatuTe Integration: Idea Proposal

We think a simple SatuTe integration into IQ-TREE is a good starting point. It begins with branch-level saturation testing for either all branches of a fixed tree or a user-defined subset, using a single alignment and reversible stationary models.

This looks feasible because IQ-TREE already contains most of the required machinery. Partial likelihood vectors are stored on branches in [phylonode.h](../../tree/phylonode.h), branch likelihoods are evaluated through [phylotree.h](../../tree/phylotree.h), and the relevant eigenvectors and eigenvalues are available in [modelmarkov.h](../../model/modelmarkov.h). The natural runtime restriction would be `useRevKernel()` in [modelsubst.h](../../model/modelsubst.h).

After simulated-data validation, the first implementation uses scalar branch-side pruning instead of reading IQ-TREE's packed/vectorized branch partial buffers directly. The tested formula converts ordinary side partials to posterior state probabilities with stationary frequencies, projects those posteriors onto the relevant non-zero right eigenvectors, and uses the product of the left/right factors as the per-site coherence. Native `--satute` now emits the published dominant statistic, an unweighted all-mode comparator and the eigenvalue-weighted comparator.

The implementation could remain small. We could add `tree/satute.cpp` and `tree/satute.h`, register them in [tree/CMakeLists.txt](../../tree/CMakeLists.txt), and add `PhyloTree` entry points for one branch, a user-defined set of branches, or all branches in the fitted tree. A minimal interface such as `--satute`, `--satute-alpha NUM`, and `--satute-edges FILE` would be enough to start.

Outputs are `.sat.stat`, `.sat.tree`, `.sat.tree.nex` and `.sat.branch`. The branch table reports, in plain terms, the branch identifier, formula, IQ-TREE rate category, IQ-TREE rate multiplier, estimated coherence value, test statistic, p-value, chosen significance level, adjusted significance level, the sizes of the two parts of the tree defined by the branch, the split label and the final result of the test. For discrete rate-category models such as `+G4`, the implementation consumes IQ-TREE's maximum-posterior pattern-rate assignments and fitted category multipliers, evaluates each category on a rate-rescaled tree and writes both category rows and pooled rows. Pure `+I` is not converted into category-wise SatuTe output because IQ-TREE does not emit per-site category rows for that model; `+I` combined with IQ-TREE-supported discrete rate models is handled through the same `computePatternRates` path. Tree annotations remain backward-compatible by using the pooled dominant statistic. Overall, this keeps the initial IQ-TREE integration modest while supporting the enhanced eigenvalue-weighted analysis. One of the biggest practical problems is that without a visual depiction, or at least a correct split definition, it can be hard to identify the exact branch we mean.
